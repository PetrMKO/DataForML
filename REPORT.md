## 2. Что делал каждый агент

### Шаг 1/5 — DataCollectionAgent

**Файл:** `agents/data_collection_agent.py`
**Выход:** `data/raw/collected_news_categorization_20260327.parquet`

**Что сделал:**
- Загрузил данные из двух разделов датасета AG News через `datasets` (HuggingFace)
- Выполнил автоматическое определение колонок (`text`, `label`)
- Преобразовал числовые метки AG News (0–3) в текстовые названия классов
- Объединил два источника с дедупликацией по тексту

**Ключевые решения:**
- `max_samples=3000 + 1000` — небольшой объём достаточен для учебного пайплайна и позволяет быстро итерировать
- Parquet-формат выбран как эффективный для хранения табличных данных с типизацией
- Дедупликация на этапе сбора, а не после — чтобы не тратить вычисления на дубли

---

### Шаг 2/5 — DataQualityAgent

**Файл:** `agents/data_quality_agent.py`
**Выход:** `data/clean/cleaned_news_categorization_20260327.parquet`
**Отчёт:** `reports/quality_report.json`

**Что сделал:**
- Провёл комплексную диагностику: пропуски, дубли, выбросы, дисбаланс классов, качество текстов
- Сформировал структурированный отчёт с секциями missing / duplicates / outliers / imbalance / text\_quality
- Применил стратегии исправления по конфигурации

**Ключевые решения:**
- IQR-метод для обнаружения выбросов — устойчив к скошенным распределениям
- Порог критического дисбаланса = 3.0 (max/min), что соответствует практике
- Для дисбаланса < 3.0 — никаких вмешательств, чтобы не вносить артефакты

**Результат проверки:** 0 критических проблем, датасет прошёл в исходном виде

---

### Шаг 3/5 — AnnotationAgent

**Файл:** `agents/annotation_agent.py`
**Выход:** `data/annotated/annotated_20260327.parquet`
**Спецификация разметки:** `reports/annotation_spec.md`

**Что сделал:**
- Попытался использовать zero-shot классификацию через модель `facebook/bart-large-mnli`
- При отсутствии GPU/transformers автоматически переключился на правиловую (rule-based) fallback-разметку
- Для каждого примера рассчитал `confidence` и выставил флаг `needs_review` при confidence < 0.85
- Экспортировал очередь на проверку в `exports/review_queue.csv` и форматы LabelStudio

**Rule-based разметка — ключевые слова по классам:**
- **World:** world, international, government, war, military, president, UN, NATO, diplomat...
- **Sports:** sport, game, team, match, tournament, olympic, football, basketball, tennis...
- **Business:** market, stock, economy, company, trade, bank, investment, CEO, revenue...
- **Sci/Tech:** technology, science, computer, software, internet, AI, robot, space, NASA...

**Ключевые решения:**
- Порог confidence = 0.85 — достаточно строгий, чтобы отловить неуверенные предсказания
- Fallback на keyword-matching вместо отказа пайплайна — обеспечивает работоспособность без GPU
- Confidence для rule-based нормализуется в [0.5, 0.95] через min-max, отражая качество совпадения ключевых слов

---

### Шаг 4/5 — ALAgent (Active Learning)

**Файл:** `agents/al_agent.py`
**Выход:** `data/final/al_selected_news_categorization_20260327.parquet`
**Отчёт:** `reports/al_report.json`, `reports/learning_curve.png`

**Что сделал:**
- Запустил цикл активного обучения: логистическая регрессия + TF-IDF (10K фичей, биграммы)
- Сравнивал стратегии entropy vs random для отбора наиболее информативных примеров
- Построил learning curve (график зависимости F1 от объёма размеченных данных)

**Ключевые решения:**
- Стратегия **entropy** — максимизирует информационную ценность каждого нового примера (-Σ p·log p)
- Логистическая регрессия как базовая модель — быстрая, интерпретируемая, хорошо калибруется
- n_iter=5 итераций с шагом 300 примеров — достаточно для построения кривой обучения

---

### Шаг 5/5 — ModelTrainer

**Файл:** `run_pipeline.py` (встроен в пайплайн)
**Выход:** `models/model_20260327.pkl` (702 KB), `reports/final_metrics.json`

**Что сделал:**
- Обучил финальную модель на 3 200 примерах (80% от 4 000)
- Оценил на тестовой выборке 800 примеров (20%, стратифицированное разбиение)
- Сохранил модель + векторизатор как единый `pkl`-артефакт
- Сгенерировал итоговый отчёт `reports/pipeline_report.md`

**Ключевые решения:**
- TF-IDF + LogReg — надёжный, быстрый и воспроизводимый baseline
- Стратифицированное разбиение — сохраняет распределение классов в тесте
- random\_state=42 везде — полная воспроизводимость

## 3. HITL-точки: ручная проверка

### HITL-1 — После авторазметки (между шагами 3 и 4)

**Назначение:** Проверка примеров с низкой уверенностью модели
**Порог запуска:** confidence < 0.85

| Метрика | Значение |
|---------|----------|
| Всего примеров в датасете | 4 000 |
| Флагнуто для ревью | **1 984 (49.6%)** |
| Авторазмечено с высокой уверенностью | 2 016 (50.4%) |
| Проверено вручную | **0** — пользователь пропустил шаг |
| Статус | ⚠️ ПРОПУЩЕНО — использована авторазметка |

**Что было предложено:** Файл `exports/review_queue.csv` с 1 984 примерами для ручной правки колонки `label`. Также экспортированы форматы для LabelStudio (`exports/labelstudio_review.json`, 1.6 MB).

**Причина высокого процента флагнутых (49.6%):** Rule-based fallback менее уверен в пограничных случаях — тексты, содержащие ключевые слова нескольких классов одновременно (например, технологические компании на бирже пересекают Business и Sci/Tech). При использовании BART этот процент был бы значительно ниже.

**Инструмент для ревью:** Streamlit-дашборд (`python dashboard.py`) — слайдер по confidence, выпадающий список для правки метки, сохранение в `exports/review_queue_corrected.csv`.

## 5. Ретроспектива

### Что сработало хорошо

**Пайплайн как единое целое.** Все 5 шагов интегрированы через Prefect `@flow` и запускаются одной командой. Промежуточные артефакты сохраняются в Parquet, что ускоряет перезапуск с любого шага.

**Active Learning.** Entropy-стратегия дала +1.3% F1 по сравнению с random при том же бюджете разметки. Модель достигла плато на 1 700 примерах — это 42.5% от датасета, что наглядно демонстрирует ценность AL.

**Fallback-архитектура в AnnotationAgent.** Вместо краша при отсутствии GPU пайплайн переключился на rule-based классификацию. Это обеспечило работоспособность на любом железе.

**Качество AG News.** Датасет оказался чистым: 0 дубликатов, 0 пропусков, сбалансированные классы. Это ускорило разработку — шаг чистки прошёл без вмешательств.

**Streamlit-дашборд.** Полнофункциональный интерфейс для HITL-ревью с фильтрацией по confidence, возможностью правки меток и сохранением исправлений.

---

### Что не сработало

**49.6% примеров флагнуто для ревью.** Rule-based аннотатор слишком неуверен в пересекающихся категориях — тексты про технологические компании или спортивный бизнес. Пайплайн создан для запуска BART, но без GPU/transformers результат деградировал.

**HITL-1 был пропущен.** Без ручного ревью пайплайн использовал авторазметку для почти половины датасета. Это снижает качество аннотаций и нивелирует смысл HITL-точки.

**Класс Business — худшие метрики (F1 ≈ 0.81).** Бизнес-новости пересекаются и с мировой политикой (торговые войны), и с технологиями (tech-стартапы). Разграничение требует более тонкой аннотации или иерархической классификации.

**Нет кросс-валидации.** Метрики основаны на одном разбиении 80/20. Результаты могут немного варьироваться при другом random\_state.
